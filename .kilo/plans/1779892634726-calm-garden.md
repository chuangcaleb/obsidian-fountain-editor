# Plan: 2026 Release Workflow Update

## Design Decisions (confirmed)

| Decision | Choice | Rationale |
|---|---|---|
| Tag format | Bare semver (`1.4.9`, no `v`) | Obsidian plugin spec requires this |
| Changesets | Remove | Overkill for single-package plugin |
| PR CI | Add | `lint + typecheck + build` on every PR to master |
| Release mode | Immediate publish | No draft step |
| Node.js | `lts/*` | Auto-follows latest LTS |
| Action versions | Latest | `checkout@v4`, `setup-node@v4`, `cache@v4`, `pnpm/action-setup@v4` |
| Release tool | `gh release create` | Replace deprecated `actions/create-release@v1` + `upload-release-asset@v1` |
| Zip archive | Skip | Individual files only |
| Changelog | Hybrid | `--generate-notes` + link to CHANGELOG.md in release body |
| CHANGELOG.md | Keep manually | Continue maintaining by hand |

## Changes

### 2. Add `.github/workflows/ci.yml`

```yaml
name: CI

on:
  pull_request:
    branches: [master]
  push:
    branches: [master]

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          run_install: false
      - uses: actions/setup-node@v4
        with:
          node-version: lts/*
          cache: pnpm
      - run: pnpm install
      - run: npx tsc --noEmit   # typecheck
      - run: npx xo             # lint
      - run: pnpm build         # build
```

### 3. Rewrite `.github/workflows/release.yml`

Replace deprecated action-based workflow with `gh release create`:

```yaml
name: Build obsidian plugin

on:
  push:
    tags: ["*"]

env:
  PLUGIN_NAME: obsidian-fountain-editor

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          run_install: false
      - uses: actions/setup-node@v4
        with:
          node-version: lts/*
          cache: pnpm
      - run: pnpm install
      - run: pnpm build
      - name: Create Release
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          tag="${GITHUB_REF#refs/tags/}"
          gh release create "$tag" \
            --title="$tag" \
            --generate-notes \
            build/main.js build/manifest.json build/styles.css
```

Key changes from current:
- `actions/checkout@v3` → `@v4`
- `actions/setup-node@v1` → `@v4` with `node-version: lts/*` + `cache: pnpm`
- `pnpm/action-setup@v2` → `@v4`
- `actions/cache@v3` block removed (replaced by `cache: pnpm` in setup-node)
- `actions/create-release@v1` + 3x `upload-release-asset@v1` → single `gh release create`
- `::set-output` removed (deprecated)
- Commented-out zip step removed
- `--generate-notes` auto-generates release body from commits, user adds CHANGELOG.md link manually

### 4. Update `.npmrc`

Already has `tag-version-prefix=""` — keep as-is. This makes `pnpm version` tag as bare semver (e.g. `1.4.9`).

### 5. No change to `version-bump.mjs`

Already correct — reads version from package.json, updates manifest.json and versions.json.

## New Release Workflow (for the developer)

1. Merge feature PRs into `master`
2. Manually update `CHANGELOG.md` with curated notes for the new version
3. Stage CHANGELOG.md: `git add CHANGELOG.md`
4. Run: `pnpm version patch` (or `minor`/`major`)
   - Bumps `package.json`
   - Runs `version-bump.mjs` → updates `manifest.json` + `versions.json`
   - Creates commit including package.json, manifest.json, versions.json
   - Creates tag (e.g. `1.4.9`)
5. Push commit + tag: `git push --follow-tags`
6. CI release workflow triggers on tag:
   - Builds `main.js`, `styles.css`, copies `manifest.json`
   - Creates GitHub release with auto-generated notes + asset uploads
7. Manually add CHANGELOG link to release body
